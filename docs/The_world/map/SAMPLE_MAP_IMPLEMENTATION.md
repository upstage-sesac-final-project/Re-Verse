# 고품질 샘플 맵 기반 맵 구현 시스템 (Sample-based Map Implementation)

본 문서는 Re-Verse 프로젝트에서 고품질의 게임 경험을 제공하기 위해 도입된 **샘플 맵 기반 생성 및 연결 시스템**의 핵심 로직을 설명합니다.

---

## 1. 개요 (Overview)
과거의 AI 지형 생성 방식은 자유도는 높으나 시각적 완성도와 논리적 구조(문, 길의 배치 등)가 부족한 한계가 있었습니다. 이를 해결하기 위해 **검증된 293개의 샘플 맵 데이터셋**을 활용하여, 사용자의 의도에 맞는 최적의 맵 세트를 조립하고 연결하는 방식을 채택했습니다.

---

## 2. 맵 선택 로직: 체인 선택 (Chain Selection)
단순히 분위기가 비슷한 맵을 무작위로 뽑는 것이 아니라, 실제 게임 플레이가 가능하도록 **물리적으로 이어지는 맵 그룹**을 선정합니다.

1.  **시드(Seed) 선정**: 사용자 쿼리(예: "심해 도시")를 분석하여 가장 점수가 높은 대표 맵 하나를 먼저 선택합니다.
2.  **메타데이터 추적**: `map_metadata.json`에 기록된 `leads_to_id`(연결된 맵 ID) 정보를 바탕으로, 해당 맵과 실제로 이어져 있는 다음 장소들을 꼬리에 꼬리를 물고 탐색합니다.
3.  **세트 구성**: 탐색된 장소들 중 테마가 일치하는 것들을 우선순위로 하여 3~9개의 맵 체인을 구성합니다. (예: 항구 → 바다 → 수중 신전)

---

## 3. 데이터 자산 활용 (Assets & Metadata)
시스템은 각 맵의 시각적/물리적 정보를 두 가지 데이터 소스로부터 관리합니다.

*   **MapXXX.json**: 실제 맵의 지형 데이터(`data`)와 이벤트 배치 정보(`events`)를 담고 있는 원본 파일입니다.
*   **map_metadata.json**: 각 맵의 '이름', '태그(마을, 던전 등)', '설명', '출구 좌표 및 목적지' 정보를 요약한 인덱스 파일입니다. LLM은 이 파일을 검색하여 최적의 샘플을 결정합니다.

---

## 4. 물리 법칙 기반의 안전한 시작점 (Safe Spawn Algorithm)
샘플 맵을 가져올 때 플레이어가 벽이나 나무 속에 갇히는 현상을 방지하기 위해 **비트 연산 기반의 물리 분석 알고리즘**을 사용합니다.

### A. Tilesets.json의 Flags 분석
RPG Maker MZ의 타일셋 데이터에는 각 타일의 속성을 정의한 `flags` 배열(8,192개)이 있습니다.
*   **비트 연산 (Bitwise 0x10)**: 각 숫자를 비트 단위로 분석하여 `0x10`(십진수 16) 비트가 켜져 있는지를 확인합니다. 이 비트는 엔진에서 **"통행 불가(장애물)"**를 의미합니다.

### B. 다층 레이어 검사 (Layer 0~3)
하나의 좌표에는 바닥, 장식, 가구 등 최대 4개의 타일이 겹쳐 있습니다. 알고리즘은 레이어 0부터 3까지를 모두 훑어 **단 하나라도 통행 불가 비트가 발견되면** 그곳을 위험 지역으로 판단합니다.

### C. BFS 탐색 및 보정
AI가 제안한 시작 지점이 위험 지역일 경우, 파이썬 알고리즘이 **너비 우선 탐색(BFS)**을 수행하여 8방향으로 범위를 넓히며 가장 가까운 "안전한 땅(모든 레이어 통과 가능)"을 찾아 플레이어를 이동시킵니다. 이 과정은 서버 내부 연산으로 처리되어 **비용(Token)이 발생하지 않습니다.**

---

## 5. 지능형 워프 재연결 (Smart Warp Redirection)
샘플 맵은 수백 개의 맵이 연결된 큰 프로젝트의 일부입니다. 우리가 5개의 맵만 골랐을 때, 나머지 존재하지 않는 장소로 가는 문(Warp)들을 처리하는 로직입니다.

1.  **ID 리인덱싱**: `Map284.json`이 우리 프로젝트에서 `Map001.json`이 되었을 때, 내부의 이동 이벤트 번호를 자동으로 `1번`으로 번역합니다.
2.  **순환 리다이렉트**: 목적지가 현재 프로젝트에 없는 맵(실종된 장소)일 경우, 해당 문을 막지 않고 **프로젝트 내의 다음 순서 맵**으로 연결 대상을 바꿉니다.
3.  **안전 착륙**: 목적지가 바뀌었으므로, 플레이어가 도착하는 좌표 역시 해당 맵의 **안전한 스폰 포인트**로 강제 수정하여 게임의 영속성을 보장합니다.

---

## 6. 이벤트 보존 정책 (Event Preservation)
지형의 완성도를 극대화하기 위해 LLM이 이벤트를 새로 기획하지 않고, **제작자가 배치한 원본 이벤트**를 1순위로 사용합니다.
*   문 모양 그래픽이 있는 곳에는 항상 워프 이벤트가 존재하게 되며, NPC들은 벽 속이 아닌 길 위에 자연스럽게 서 있게 됩니다.
