## 미해결 리스크

### 🟡 맵 차단 기준 불일관

**현상**
```
"1번 맵 이벤트 추가해줘" → 게임_요소_생성 (통과)
"1번 맵 타일 바꿔줘"    → 범위_외 (차단)
```
맵 구조(타일·배경)는 차단하고 맵에 배치된 이벤트·NPC는 허용하는 게 의도지만, 프롬프트에 이 구분이 명확히 서술되어 있지 않아 경계 케이스에서 불일관한 동작이 나올 수 있음.

**개선 방향**
프롬프트의 지원하지 않는 기능 설명을 "맵 구조(타일·배경·레이어) 편집"으로 좁히고, "맵에 배치된 이벤트·NPC는 지원"임을 명시.


---

### 🟢 confidence 신뢰도 낮음

**현상**
실제 LLM 응답 confidence가 대부분 0.8~0.95로 수렴. 애매한 입력에도 높은 값을 반환해 0.7 threshold 기반 폴백이 사실상 작동하지 않음.

**개선 방향**
- confidence 대신 `추가_정보_필요` 분류 자체를 더 정교하게 튜닝
- 또는 threshold를 상향 조정 (예: 0.85) 후 효과 측정

---

### 🟢 복합 의도 미지원

**현상**
```
"슬라임 HP 올리고 드래곤도 새로 만들어줘" → 게임_요소_생성 (수정 부분 유실)
```
단일 입력에 수정+생성이 섞이면 하나만 처리됨. 사용자는 두 작업이 모두 처리될 것으로 기대.

**개선 방향**
Router 레벨에서 복합 의도를 감지해 `추가_정보_필요`로 유도하거나, 여러 인텐트를 리스트로 반환하는 구조로 확장 (아키텍처 변경 필요).
